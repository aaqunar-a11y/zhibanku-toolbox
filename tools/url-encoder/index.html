URL 编解码工具 — 在线 URL 编码与解码

URL 编解码工具用来处理网址里的中文、空格和特殊符号。把要处理的网址或参数粘贴到上方输入框，选好 encodeURIComponent、encodeURI 或解码模式，点「开始转换」按钮，处理结果会显示在下方结果框里，直接取用即可。反过来，把编码过的字符串粘进输入框、切到解码模式再点「开始转换」，就能还原成可读文字，全程在当前浏览器里完成。

三种模式的区别

模式不转义哪些字符典型用途
encodeURIComponent 仅 A-Z a-z 0-9 - _ . ! ~ * ' ( ) 查询参数的值、路径片段。最常用
encodeURI 上述字符 + ; , / ? : @ & = + $ # 编码一整条 URL，保留其结构符号
decodeURIComponent — 把 %E4%B8%AD 这类编码还原成原文

最常见的误用：用 encodeURI 去编码参数值。因为它不转义 & 和 =，参数值里含有这些符号时会破坏 URL 结构。参数值请一律使用 encodeURIComponent。

常见字符对照

原字符编码后说明
空格%20在查询串里也常被写成 +，但那是 application/x-www-form-urlencoded 的约定，不是 URL 标准本身
中%E4%B8%ADUTF-8 三个字节，每个字节一个百分号
&%26参数分隔符，出现在值里必须转义
=%3D键值分隔符，出现在值里必须转义
?%3F查询串起始符
#%23片段标识符，不发给服务器
/%2F路径分隔符；在参数值里转义可避免被当作路径
+%2B本身是合法字符，但表单编码中代表空格，容易混淆

注意事项

  • encodeURIComponent 转义的字符更多，适合查询参数值；encodeURI 会保留问号、等号、斜杠等结构符号，用错会导致链接打不开
  • 已经编码过的字符串再编码一次会出现 %25 这类双重转义，粘贴前先判断内容是否已编码
  • 空格编码后是 %20，而表单里常用加号表示空格，解码时加号可能被还原成空格
  • 解码模式选错会得到乱码或原样返回，建议先用一小段已知内容试一下
  • 输入内容只在当前标签页内处理，不上传服务器，但刷新或关闭页面后输入框会清空
  • 几万字符以上的超长文本会让页面短暂卡顿，建议分段处理

常见问题

为什么解码时报 “URI malformed”？
输入里存在孤立的 %，或百分号后不是两位十六进制（如 %ZZ、%E4%B8 被截断）。本工具会捕获该错误并在下方提示，而不会让页面崩掉。
编码后大小会变大吗？
会。UTF-8 下一个中文字符占 3 字节，编码后变成 %XX%XX%XX，即 9 个 ASCII 字符，长度约为原文的 3 倍。这也是查询串不宜塞入大段中文的原因。
空格到底应该是 %20 还是 +？
URL 标准（RFC 3986）里空格是 %20。+ 表示空格只适用于表单提交（application/x-www-form-urlencoded）。本工具输出 %20，这是更安全的选择。
应该对整个 URL 编码吗？
通常不应该。整条 URL 编码会把 ://、/、? 也转义掉，得到的字符串不再是可用链接。正确做法是只对参数值逐个编码。
数据会被上传吗？
不会。页面没有任何网络请求，转换完全由浏览器内置的 encodeURIComponent / decodeURIComponent 完成。

怎么用

  1. 把要处理的原始文本粘进上方输入框，比如带中文和空格的链接。
  2. 选编码模式：encodeURIComponent 适合参数值，encodeURI 适合整条地址。
  3. 点「编码」按钮，下方立刻给出百分号编码结果，点复制就能拿去用。
  4. 要还原时切到解码模式，粘贴编码串再点「解码」，得到原始文本。

适用场景

  • 拼接带中文参数的接口地址，避免服务端收到乱码。
  • 把分享链接里的空格和井号转义，发出去不会断链。
  • 调试时把编码串还原，看清原始参数到底是什么。

常见问题

编码和解码有什么区别

编码是把普通文本转成浏览器和服务器都能安全传输的百分号形式，解码则是把这个形式还原成你原来输入的文字。方向选反了看到的就是乱码，按需切换即可。

encodeURIComponent 和 encodeURI 该用哪个

前者会把问号、井号、斜杠这些也一起转掉，适合放在参数值里；后者保留这些分隔符，适合处理整条地址。拿不准时按用途选前者更稳妥。

我粘进去的内容会被上传吗

不会。整个过程在你的浏览器里完成，页面不发请求，关掉标签页内容就没了，可以放心处理敏感链接。
